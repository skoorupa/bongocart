# Turniej — plan implementacji

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tryb turniejowy: N map (domyślnie 10) z sumowaniem punktów i czasu, tabela po każdej mapie i pod `Tab`, gotowość graczy między mapami z wymuszeniem startu przez hosta.

**Architecture:** Czysty moduł `src/tournament.js` trzyma stan turnieju (zamrożony skład, tabela, gotowość, fazy). Host (lub solo) jest jego jedynym właścicielem; klienci dostają gotowy widok w wiadomości `tourney`. `createGame` przyjmuje opcjonalny zamrożony `roster`. `main.js` spina przepływ map, `src/ui/tournamentView.js` rysuje tabelę.

**Tech Stack:** czysty JS (moduły ES), PeerJS przez istniejący `session.js`, `node --test`.

**Spec:** `docs/superpowers/specs/2026-11-01-turniej-design.md`

## Global Constraints

- Komentarze po polsku; stałe w `src/config.js` (`TOURNAMENT`), bez magicznych liczb.
- Logika (`tournament.js`, `game.js`, `net/*`) bez DOM; rysowanie tylko w `ui/*` i `main.js`.
- Determinizm: seedy map z `mapSeed(i) = "<seed>-<i+1>"`; żadnego `Math.random` w logice.
- Wszystko od klientów niezaufane — walidacja w `session.js`/`protocol.js`.
- Podbić `GAME_VERSION` na `'0.11.0'`.
- Tryb `race` działa jak dotąd (istniejące testy bez zmian zachowania).
- Commity po polsku z prefiksem „Turniej:”. Pełne `npm test` zielone na końcu każdego zadania.

## Review Focus

1. Host przerywa turniej w połowie (menu) — klienci wracają do lobby, następny start to świeży turniej (nie kontynuacja).
2. Gracz wychodzi w fazie `between` — gotowość liczy się bez niego (nie blokuje startu), a w kolejnej mapie jego kart jedzie bot pod jego nazwą.
3. Klient dostaje `tourney` zanim pokaże wyniki (opóźnienie `RACE.resultsDelaySeconds`) albo po — widok tabeli aktualizuje się w obu przypadkach.
4. Wiadomość `tourney` ze śmieciami (złe typy, za długa tabela, nazwy ze znakami sterującymi) — klient nie wysypuje się (sanityzacja).
5. `Tab` w lobby / w polu tekstowym nie jest blokowany (tylko w trakcie wyścigu turniejowego).

**Interfaces:**
- Produces:
  - `TOURNAMENT = { points: [15, 12, 10, 8, 6, 4, 2, 1], modes: { race: {label:'Pojedynczy wyścig'}, tournament: {label:'Turniej'} } }`
  - schemat: `{ key:'gameMode', type:'select', label:'Tryb gry', options: optionsOf(TOURNAMENT.modes), default:'race' }`, `{ key:'mapCount', type:'int', label:'Liczba map (turniej)', min:2, max:15, step:1, default:10 }`
  - `createTournament({ seed: string, mapCount: number, roster: Array<{id,name,color,isHuman}> })` → obiekt:
    - pola: `roster` (kopia), `index` (0..), `count`, `phase` (`'racing'|'between'|'done'`)
    - `mapSeed(i): string` → `mapSeedOf(seed, i)`
  - eksport `mapSeedOf(seed: string, i: number): string` → `` `${seed}-${i + 1}` `` (też dla podglądu w lobby)
    - `recordRace(race): void` — punkty wg `standings(race)` (z `race.js`), czas `finishTime ?? race.time`; `phase = 'between'` (albo `'done'` po ostatniej mapie)
    - `table(): Array<{id, name, color, isHuman, points, time, lastPoints, left}>` posortowane: punkty ↓, czas ↑, kolejność rosteru
    - `setReady(id): boolean` (true = zmiana; tylko ludzie z rosteru, nie `left`, w fazie `between`)
    - `allReady(): boolean` — każdy człowiek nie-`left` jest gotowy
    - `markLeft(id): void`
    - `nextMap(): void` — `index++`, czyści gotowość, `phase = 'racing'`
    - `view(): {index, count, phase, table, ready: string[]}` — to, co idzie w wiadomości `tourney`
